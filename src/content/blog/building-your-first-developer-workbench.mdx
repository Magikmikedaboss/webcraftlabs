<LabSection
  number="01"
  eyebrow="The Problem"
  title="Beginners don't need more tools. They need a workbench."
>

Learning to code can feel like walking into a hardware store during an earthquake.

Everyone is yelling about different tools.

One person says you need React. Another says Python. Another says Docker. Someone else is whispering about Kubernetes from a dark hallway.

Before long, you have forty browser tabs open, six apps installed, three tutorials half-finished, and no actual project built.

That is not learning. That is tool fog.

<LabNote title="Notebook Entry">
A beginner developer does not need the perfect setup.
They need a simple setup that helps them start building.
</LabNote>

Think of coding like building a workshop.

You do not start with every machine in the building. You start with a clean bench, a few reliable tools, and enough space to make your first mess.

That is what we are building here.

</LabSection>

<LabSection
  number="02"
  eyebrow="The Workbench"
  title="Start with a code editor."
>

Your code editor is where most of the work happens.

It is your desk. Your notebook. Your command center.

For beginners, the easiest recommendation is simple: **Use VS Code.**

It is free, widely used, and works for almost every kind of beginner project.

<LabObservation title="Observation">
Do not spend your first week customizing your editor.
Write code first. Make it pretty later.
</LabObservation>

A good beginner setup only needs a few things:

- A clean theme
- Auto-formatting
- JavaScript and TypeScript support
- A built-in terminal
- Git integration

That is enough.

You are not trying to build a spaceship yet. You are trying to get the engine to turn over.

</LabSection>

<LabSection
  number="03"
  eyebrow="The Browser"
  title="Your browser is also a developer tool."
>

Most beginners think the browser is only where websites appear.

Developers know the browser is also where websites confess their secrets.

Open Developer Tools and suddenly you can inspect HTML, test CSS, watch network requests, debug JavaScript, and see why your layout decided to fall down the stairs.

Use Chrome, Firefox, Edge, or Arc. Any modern browser works.

The important part is learning the developer tools.

<LabNote title="Beginner Rule">
When something looks broken, inspect it.
The browser usually knows where the body is buried.
</LabNote>

</LabSection>

<LabSection
  number="04"
  eyebrow="The Terminal"
  title="The terminal is not scary."
>

The terminal looks intimidating because it has no buttons. Just a blinking cursor. Very dramatic.

But the terminal is really just another way to talk to your computer. Instead of clicking buttons, you type instructions.

You will use it for things like creating projects, installing packages, running a development server, starting builds, and checking Git status.

At first, you only need a few commands:

```bash
npm install
npm run dev
git status
git add .
git commit -m "first commit"
```

That is plenty.

<LabObservation title="Observation">
The terminal feels weird until it feels normal.
Then one day you will open it without thinking, and that is when the wizard robe appears.
</LabObservation>

</LabSection>

<LabSection
  number="05"
  eyebrow="Version Control"
  title="GitHub gives your code a home."
>

Every beginner should learn Git and GitHub early.

Not because it is glamorous. It is not.

Git is a time machine with a user interface designed by a sleepy octopus.

But it matters.

Git lets you save versions of your work. GitHub gives those versions a place to live online.

Think of commits as checkpoints in a video game. When things break — and they will — you can go back.

<HandSketch title="Git, Explained Poorly but Usefully">
Your Code
↓
Save a Checkpoint
↓
Push to GitHub
↓
Project Has a Home
</HandSketch>

You do not need to master Git on day one. Start with:

```bash
git add .
git commit -m "initial project setup"
git push
```

That is the beginner doorway. Walk through it.

</LabSection>

<LabSection
  number="06"
  eyebrow="AI Assistant"
  title="Use AI, but don't let it drive blindfolded."
>

AI can be an incredible learning tool.

Use ChatGPT, Claude, Cursor, Copilot, or whatever tool fits your workflow.

But use AI like a pair programmer, not a vending machine.

**Bad use:** "Build my entire app and I will paste whatever you give me."

**Better use:** Explain this error. Review this component. Why is this code not working? Show me a simpler version. Teach me what this function does.

<LabNote title="Important">
AI can help you move faster.
But if you never understand what it gives you, you are not learning to code.
You are just renting a brain with spotty Wi-Fi.
</LabNote>

</LabSection>

<LabSection
  number="08"
  eyebrow="Ignore List"
  title="Tools you can ignore for now."
>

This might be the most important section.

Beginners waste a lot of time learning tools they do not need yet.

You can safely ignore these at the beginning:

- Kubernetes
- Microservices
- Complex Docker setups
- Advanced AWS architecture
- Redis
- Message queues
- Monorepos
- GraphQL
- Design systems
- Performance budgets
- CI/CD pipelines

Those tools matter later. But not before you can build and ship a simple project.

<LabStamp>Not Yet</LabStamp>

<LabObservation title="Observation">
The best beginner stack is not the most powerful stack.
It is the stack that removes friction.
Less friction means more building. More building means more learning.
</LabObservation>

</LabSection>

<LabVerdict title="The Lab's Recommendation">

Your first developer setup does not need to be perfect. It needs to be usable.

Start with: **VS Code. Node.js. GitHub. A browser. Vercel. An AI assistant.**

That is enough.

Do not collect tools like digital souvenirs.

Build something. Break it. Fix it. Ship it.

Then do it again.

That is how a beginner becomes a developer.

</LabVerdict>
